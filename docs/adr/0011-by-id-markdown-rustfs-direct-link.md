# By-id paper markdown via `papers`/`paper_assets`: lazy suspend-and-wait returning a RustFS direct link

_Implements the read surface ADR `0007` decided, on top of the `papers`/`paper_assets` schema from
ADR `0009`._

`GET /api/papers/{id}/markdown` (and `/pdf`) already speaks the async LRO contract — `202 Accepted`
+ `Operation-Location` + `Retry-After`, poll `…/status`, re-GET on completion — but it resolves
assets **directly against the object store** and, on a hit, **streams the markdown bytes** back
through qatlasd. With ADR `0009` giving each work a catalog row and a child `paper_assets` table, the
read path should resolve **through the catalog** and hand back a **direct object-store link** rather
than proxy bytes (handoff §5c).

## Decision

- **By-id resolution through the catalog.** A read by any of the three external ids
  (`arxiv` / `doi` / `openalex`, each `UNIQUE` on `papers`) resolves
  `papers` → `paper_default_asset_id` → `paper_assets.mineru_md_path`. The default-asset pointer
  (ADR `0009` Q21: published-first, else latest arXiv) decides *which* asset's markdown is served
  for a bare by-paper read. Batch id → metadata resolution stays on `GET /api/papers/lookup`
  (ADR `0007`).
- **Lazy suspend-and-wait, not 404-on-miss.** When the resolved asset has no `mineru_md_path` yet,
  keep the existing LRO: `202` + `Operation-Location`, background silent fetch-PDF + MinerU convert,
  caller polls `…/status` until `md_ready`. A corpus hit QA does not yet host can thus *become*
  hosted (ADR `0007`) instead of hard-missing.
- **The terminal 200 returns a RustFS direct link, not bytes.** On completion the endpoint hands
  back a **presigned (or public) RustFS URL** to the markdown object — the same short-lived-presign
  pattern already used for the MinerU-claim `pdf_url` — so qatlasd stays out of the large-object
  data path and the edge/object store serves the bytes.
- **Docs auto-generated.** The route's OpenAPI stub lives in `internal/routes/openapi.go`,
  regenerated by `pixi run swagger` (CI drift-guard); the human reference is `docs/server/rest-api.md`.

## Why a direct link, not a byte stream

- **Keep the server out of the byte path.** Markdown bundles (and PDFs) are large and already sit in
  RustFS behind the edge's public endpoint; presigning a GET lets the object store / edge serve them
  directly instead of tunnelling every byte through qatlasd.
- **Reuse a proven pattern.** The MinerU-claim flow already returns a 24h-TTL presigned RustFS GET
  for the PDF; markdown reads reuse it verbatim, including the graceful fallback when a backend
  cannot presign (dev `LocalStore`).
- **Short-lived by construction.** A presigned URL expires, so it is a fetch handle, not a
  redistributable channel.

## Why keep the LRO rather than 404 on a missing markdown

References and reads target *works*, and a work QA holds in the OpenAlex corpus but has not yet
converted is a normal, recoverable state — the suspend-and-wait contract lets the first reader
trigger materialisation and get the result, which is exactly the agent-friendly behaviour ADR `0007`
relies on ("a corpus hit … can later … become a hosted Paper").

## Considered options

- **Stream markdown bytes through qatlasd (status quo).** Rejected: puts the server on the
  large-object data path the object store already fronts.
- **404 when markdown is absent.** Rejected: breaks the lazy-materialise contract; a fetchable,
  not-yet-converted work would look permanently missing.
- **Return an internal re-GET URL (`/api/papers/{id}/markdown`) instead of a direct object link.**
  Rejected: adds a redundant server round-trip to fetch bytes qatlasd should not proxy in the first
  place.

## Consequences

- **Success shape changes (Phase C).** The markdown `200` returns a direct-link payload instead of
  `text/markdown` bytes — a breaking change for any current byte consumer (pre-launch, acceptable);
  `/pdf` may adopt the same shape. `docs/server/rest-api.md` + the OpenAPI spec are regenerated.
- **Depends on ADR `0009`.** The handler reads `papers`/`paper_assets`; it lands with, not before,
  Phase A.
- **No new write path.** This is a read capability under `papers:read`, consistent with the QA/lean
  boundary (ADR `0007`/`0008`): QA exposes read-only paper substrate; it never authors lean content.
